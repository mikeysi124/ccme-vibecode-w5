▶ เปิดแอปคัดกรอง ER/OPD ดูผลชุดทดสอบในแอป (แท็บ “ทดสอบ”) — 29 เคส

ปัญหาที่แก้ (ต่อเนื่องจาก Problem Statement วิชา 3)

พยาบาลคัดกรองหน้าห้องฉุกเฉินต้องจัดระดับความเร่งด่วน 1–5 ภายในไม่กี่นาที โดยเทียบเกณฑ์ราว 50 ข้อจากความจำ และระดับที่ให้กำหนดช่องทาง ER หรือ OPD โดยอัตโนมัติ เคสก้ำกึ่งที่รอยต่อระดับ 2/3 จึงมักถูกดันขึ้นเพื่อความปลอดภัย ทำให้ผู้ป่วยที่ควรไป OPD ไหลเข้า ER

ระบบนี้เสนอระดับและช่องทาง พร้อมแสดงข้อเกณฑ์ที่เข้า/ไม่เข้าเป็นรายข้อ โดยพยาบาลเป็นผู้ตัดสินสุดท้ายเสมอและ override ได้ทุกครั้ง

ฟีเจอร์ที่ทำงานจริง

  • รับข้อมูลแบบแตะเลือก — อาการนำ · อายุ (ปี/เดือน) · GCS · สัญญาณชีพ · pain score พร้อมตรวจค่าที่เป็นไปไม่ได้ (เช่น ชีพจร 400) ก่อนประเมิน
  • Criteria engine เดินตาม 4 จุดตัดสินใจ ก–ง ของคู่มือ MOPH ED Triage 2561 ผลลัพธ์ deterministic — ใส่ข้อมูลเดิมได้คำตอบเดิมเสมอ ไม่มีการสุ่ม ไม่เรียก AI
  • อ้างเกณฑ์รายข้อพร้อมเลขหน้าคู่มือ และแยกให้เห็น 3 กลุ่ม: เข้าเกณฑ์ · ตัดสินไม่ได้เพราะข้อมูลไม่ครบ · ไม่เข้าเกณฑ์
  • สลับชุดเกณฑ์ได้โดยไม่แก้โค้ด — มีให้เลือก 2 ชุด (ฉบับคู่มือ และฉบับโรงพยาบาลที่ใช้จุดตัดตามอายุ) หรือโหลดไฟล์ .json ของโรงพยาบาลเองเข้ามา
  • ยืนยัน / override พร้อมเหตุผล → เกิด audit trail และสรุปอัตราการแก้ระดับ (ดันขึ้น/ลดลง)
  • ตารางเคส + ส่งออก CSV (UTF-8 BOM เปิดใน Excel ภาษาไทยไม่เพี้ยน)
  • Known-Answer Test ในตัว 29 เคส — รวมตัวอย่างที่คู่มือเฉลยไว้เอง

ที่มาของเกณฑ์

ชุดหลัก: กรมการแพทย์ กระทรวงสาธารณสุข. MOPH ED. TRIAGE. พิมพ์ครั้งที่ 1 (2561) — แปลจาก ESI ใช้ 4 หัวข้อเป็นจุดตัด (ถอดความจาก text layer ของเล่ม พร้อมเลขหน้ากำกับทุกข้อ)

ชุดฉบับโรงพยาบาล: ชุดหลัก + จุดตัดตามอายุจาก วิธีปฏิบัติ PMK-WND-037 การคัดกรองผู้ป่วยนอก รพ.พระมงกุฎเกล้า (2561) — ระบุที่มารายข้อในแอป

เหตุผลที่ต้องมี 2 ชุด: คู่มือ MOPH ใช้เกณฑ์ shock SBP < 90 เท่ากันทุกช่วงอายุ ถ้าใช้ตรงตัวกับทารกจะได้ระดับ 1 แทบทุกราย — แอปแสดงผลตามที่คู่มือเขียนโดยไม่แก้ให้เอง แต่เปิดให้สลับไปใช้ชุดที่มีจุดตัดตามอายุได้ (ดูเคส 20b เทียบ 20c ในแท็บทดสอบ)

วิชา 5 Part 2 — Frontend–Backend Integration

แอปเชื่อม Supabase (PostgreSQL) ผ่าน client SDK แล้ว ทำ CRUD ครบสี่คำสั่งบนตารางจริงตาม ERD:

  • POST บันทึกเคส → cases → assessments → assessment_criteria → overrides
  • GET อ่านเคสพร้อมข้อมูลผู้ป่วย เกณฑ์ที่เข้า และการแก้ระดับ ในคำขอเดียว
  • PUT แก้ระดับที่ตัดสินจริงและเหตุผลในตาราง overrides
  • DELETE ลบเคส โดย assessments / criteria / overrides หายตาม cascade

ความปลอดภัยหลายชั้น: Supabase Auth → RBAC จากคอลัมน์ role ใน profiles → validation ทั้งฝั่งหน้าเว็บและ CHECK constraint → RLS ทุกตาราง เทียบ auth.uid() กับเจ้าของแถว

กุญแจ: ค่าเชื่อมต่ออยู่ใน supabase-config.js ที่ไม่ขึ้น GitHub — หน้าเว็บสาธารณะนี้จึงทำงานในโหมด localStorage · การสาธิต CRUD รันจากเครื่องที่มีไฟล์ตั้งค่า
