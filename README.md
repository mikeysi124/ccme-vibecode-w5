## ปัญหา

พยาบาลคัดกรองหน้าห้องฉุกเฉินโรงพยาบาลรัฐต้องจัดระดับความเร่งด่วน 1–5 ให้ผู้ป่วยทุกรายภายในไม่กี่นาที
โดยเทียบเกณฑ์คู่มือ MOPH ED Triage ราว 50 ข้อจากความจำ และ**ระดับที่ให้จะกำหนดช่องทาง ER หรือ OPD โดยอัตโนมัติ**
(ระดับ 1–2 → ER · ระดับ 3–5 → OPD ในเวลา หรือแพทย์เวรนอกเวลา)

เมื่อเจอเคสก้ำกึ่งที่ไม่มั่นใจ พยาบาลจะดันระดับ 3 ขึ้นเป็น 2 เพื่อความปลอดภัย → ผู้ป่วยที่ควรไป OPD ไหลเข้า ER
**รอยต่อระดับ 2/3 จึงเป็นเส้นแบ่ง ER/OPD ที่แท้จริง** และเป็นจุดที่เครื่องมือนี้เจาะ

ไม่มีเครื่องมือใดบอกพยาบาล ณ จุดตัดสินใจว่า "เข้าเกณฑ์ข้อไหน" — ปัญหาไม่ใช่พยาบาลไม่เก่ง
แต่คือเกณฑ์ซับซ้อน + เวลาบีบ + ไม่มีตัวช่วยอ้างอิงรายข้อ

## ผู้ใช้

- **ผู้ใช้หลัก:** พยาบาลคัดกรอง — ใช้บนมือถือ/แท็บเล็ตข้างจุดคัดกรอง **เป็นผู้ตัดสินสุดท้ายเสมอ**
- **ผู้ใช้รอง:** แพทย์ ER/OPD (รับผลการจัดช่องทาง) · หัวหน้าพยาบาล (audit คุณภาพคัดแยก)
- **ไม่ใช่ผู้ใช้:** ผู้ป่วยประเมินตนเอง

## สิ่งที่ระบบทำ / ไม่ทำ

| ทำ | ไม่ทำ |
|---|---|
| เสนอระดับ + ช่องทาง ตามเกณฑ์ที่โหลดไว้ | ไม่ตัดสินแทนพยาบาล |
| แสดงข้อเกณฑ์ที่เข้า/ไม่เข้า **เป็นรายข้อพร้อมเลขหน้าคู่มือ** | ไม่วินิจฉัยโรค |
| แยกให้เห็นว่าข้อไหน "ตัดสินไม่ได้เพราะข้อมูลไม่ครบ" | ไม่เดาค่าที่ยังไม่ได้วัด |
| บันทึก override + เหตุผล เกิด audit trail | ไม่เชื่อม HIS / ไม่แตะเวชระเบียนจริง |
| สลับชุดเกณฑ์ตามโรงพยาบาลได้ | ไม่เรียก LLM / ไม่มีการสุ่มใด ๆ |

## สถาปัตยกรรม

```
ผู้ใช้ (มือถือ/แท็บเล็ต)
   ↓
P49-triage.html  ← หน้าจอทั้งหมด ไม่มี build step
   ↓
engine.js        ← ตรรกะล้วน ไม่รู้จักเกณฑ์ข้อใดเลย
   ↑
criteria-*.json  ← เกณฑ์เป็น "ข้อมูล" เปลี่ยนชุด = เปลี่ยนพฤติกรรมทั้งระบบ
   ↓
localStorage     ← เคสที่บันทึก (วิชา 5 Part 2 จะย้ายไป Supabase)
```

**หลักการสำคัญ:** engine ไม่มีชื่อโรค ไม่มีตัวเลขจุดตัด ไม่มีเกณฑ์ข้อใดฝังอยู่ในโค้ดเลย
มีแต่ตัวเดินตามจุดตัดสินใจ + ตัวประเมินเงื่อนไข — เกณฑ์ทั้งหมดอยู่ในไฟล์ JSON ที่สลับได้
แม้แต่ช่องติ๊กบนหน้าจอก็สร้างจากชุดเกณฑ์ที่โหลดอยู่

## เกณฑ์ที่ใช้ และที่มา

| ชุด | ที่มา |
|---|---|
| `criteria-moph-2561.json` | กรมการแพทย์ กระทรวงสาธารณสุข. **MOPH ED. TRIAGE** พิมพ์ครั้งที่ 1 (2561) — แปลจาก ESI ใช้ 4 หัวข้อเป็นจุดตัด · ถอดความจาก text layer ของเล่ม ระบุเลขหน้าทุกข้อ |
| `criteria-moph-2561-local.json` | ชุดข้างบน + จุดตัดตามอายุจาก **วิธีปฏิบัติ PMK-WND-037 การคัดกรองผู้ป่วยนอก รพ.พระมงกุฎเกล้า** (แก้ไขครั้งที่ 1, 9 ต.ค. 2561) · ระบุที่มารายข้อ |

**4 จุดตัดสินใจ**
- **จุด ก** ต้องการ life-saving intervention → ระดับ 1
- **จุด ข** รอไม่ได้: ภาวะเสี่ยง · ภาวะซึม · ภาวะปวด → ระดับ 2
- **จุด ค** ใช้ทรัพยากรกี่อย่าง: 0 → ระดับ 5 · 1 → ระดับ 4 · ≥2 → ไปจุด ง
- **จุด ง** สัญญาณชีพช่วงอันตราย**ตามช่วงอายุ** → เข้า = พิจารณาระดับ 2 · ไม่เข้า = ระดับ 3

### ทำไมต้องมีชุดฉบับโรงพยาบาล

คู่มือ MOPH ระบุเกณฑ์ shock เป็น `SBP < 90` เท่ากันทุกช่วงอายุ ซึ่งเป็นค่าของผู้ใหญ่ —
ถ้าใช้ตรงตัวกับทารก (ความดันปกติ 85/50) จะได้ระดับ 1 แทบทุกราย
ระบบ**ไม่แก้เกณฑ์ให้เอง** เพราะหน้าที่ของเครื่องมือคือแสดงตามที่เอกสารเขียน
แต่เปิดให้สลับไปใช้ชุดที่มีจุดตัดตามอายุจาก WI ของโรงพยาบาลจริงได้
→ ดูเคส **20b เทียบ 20c** ในแท็บ "ทดสอบ" — ข้อมูลผู้ป่วยชุดเดียวกัน สลับไฟล์เกณฑ์อย่างเดียว คำตอบเปลี่ยนจากระดับ 1 เป็นระดับ 2

## การตรวจสอบความถูกต้อง

```bash
node test-engine.js      # ผ่าน 58 / 58 ข้อ
```

- **29 สถานการณ์จำลอง** — ในนั้นมี **ตัวอย่างที่คู่มือเฉลยไว้เอง** (หน้า 8–9, 11–12, 15) เช่น
  "เด็ก 10 ปี คันไม่มีผื่น → ระดับ 5", "หญิง 29 ปี ปัสสาวะขุ่น UA+UC+UPT = Lab 1 กิจกรรม → ระดับ 4"
- **เคสขอบเกณฑ์** ทุกจุดตัด — GCS 8/9 · SpO₂ 91/92 · HR 100/105 · pain 7 มี/ไม่มีลักษณะประกอบ
- **เคสความปลอดภัยเด็ก** — เด็ก 5 ปี HR 105 ต้องได้ระดับ 3 (ไม่ใช่ 2) เพราะจุดตัดของช่วงอายุนี้คือ 140
- **ตรรกะ tri-state** — "ยังไม่ได้วัด" ต้องไม่ถูกนับเป็น "ไม่เข้าเกณฑ์" เงียบ ๆ
- **ค่าขยะ** — ชีพจร 400 / SpO₂ ติดลบ / pain มีทศนิยม / ความดันล่างสูงกว่าบน ต้องถูกปฏิเสธพร้อมข้อความ
- **กันไฟล์เกณฑ์หลุดจากกัน** — ตรวจว่า `.js` ที่แอปใช้ตรงกับ `.json` ทุกตัวอักษร

ชุดทดสอบเดียวกันนี้รันในแอปได้ที่แท็บ **"ทดสอบ"**

## ข้อจำกัดและความปลอดภัย

- **เครื่องมือสาธิตเพื่อการเรียนการสอน ไม่ใช่เครื่องมือแพทย์** ยังไม่ผ่านการตรวจสอบความแม่นยำทางคลินิก
- **ใช้สถานการณ์จำลองทั้งหมด** ไม่มีข้อมูลผู้ป่วยจริง ไม่มีช่องเก็บชื่อ / HN / เลขบัตรประชาชน
- ข้อมูลที่บันทึกอยู่ใน localStorage ของเบราว์เซอร์เครื่องผู้ใช้เท่านั้น ไม่ส่งออกไปที่ใด
- คู่มือ MOPH ระบุเองว่า *"ความถูกต้อง รวดเร็ว แม่นยำของระบบการคัดกรองนี้ขึ้นอยู่ประสบการณ์ของผู้คัดกรองเป็นอย่างสูง"*
  และจุด ข *"จำเป็นต้องใช้พื้นฐานของการซักประวัติและใช้สัมผัสที่หก จากประสบการณ์"*
  → เครื่องมือนี้จึงเสนอเท่านั้น **พยาบาลเป็นผู้ตัดสินสุดท้ายเสมอ**
- ผัง ESI Algorithm Version 4 (คู่มือหน้า 6) เป็นภาพ ไม่มี text layer — ยังไม่ได้ถอดความ
