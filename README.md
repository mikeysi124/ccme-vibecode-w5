# ผู้ช่วยคัดกรองช่องทาง ER/OPD ที่อ้างอิงเกณฑ์รายข้อ · v1.2.0

Working Prototype วิชา 7 · Workshop on Vibe Coding for Clinical Innovation 2026 · ศ.น.พ.
**นพ.กิตติพศ เกียรติพัฒนาชัย · User Code P49** · 🔗 https://mikeysi124.github.io/ccme-vibecode-w5/

**ปัญหา** พยาบาลคัดกรองหน้าห้องฉุกเฉินต้องจัดระดับ 1–5 ภายในไม่กี่นาทีจากเกณฑ์คู่มือ MOPH ED Triage ราว 50 ข้อ และระดับกำหนดช่องทาง ER/OPD ทันที เคสก้ำกึ่งที่รอยต่อระดับ 2/3 จึงถูกดันขึ้นเพื่อความปลอดภัย โดยไม่มีตัวช่วยบอกว่าเข้าเกณฑ์ข้อไหน

**ผู้ใช้** พยาบาลคัดกรองบนมือถือหรือแท็บเล็ต เป็นผู้ตัดสินสุดท้ายเสมอ · ไม่ใช่เครื่องมือให้ผู้ป่วยประเมินตนเอง

## ทำอะไร
- เสนอระดับและช่องทาง พร้อมแยกข้อเกณฑ์เป็น เข้า / ตัดสินไม่ได้เพราะข้อมูลไม่ครบ / ไม่เข้า รายข้อพร้อมเลขหน้าคู่มือ
- ยืนยันหรือ override พร้อมเหตุผล บันทึกผู้บันทึกและเวลา และสรุปอัตราการแก้ระดับ · เก็บผลล่าสุด ยังไม่เก็บประวัติการแก้ซ้ำ
- สลับชุดเกณฑ์ได้โดยไม่แก้โค้ด: MOPH ED Triage 2561 และฉบับโรงพยาบาลที่มีจุดตัดตามอายุ
- ไม่เรียก AI ไม่มีการสุ่ม ข้อมูลเดิมได้คำตอบเดิมเสมอ

## ใช้อย่างไร
1. เปิดลิงก์บนมือถือ → แท็บ **คัดกรอง** กรอกอายุ สัญญาณชีพ ติ๊กอาการ → **ประเมิน**
2. ยืนยันหรือแก้ระดับ → เคสไปอยู่แท็บ **เคสวันนี้** ส่งออก CSV ได้
3. จะเก็บลงฐานข้อมูล: แท็บ **เคสวันนี้** อ่านข้อมูลที่เก็บ ติ๊กยินยอม ตอบคำถาม แล้วสมัครหรือเข้าสู่ระบบ · ไม่ยินยอมก็ใช้ได้ เคสเก็บในเครื่องนี้
4. แท็บ **ทดสอบ** รันชุดทดสอบ 29 เคส

## ความถูกต้อง
`node test-engine.js` ผ่าน 58/58 = เคสที่รู้คำตอบ 29 เคส รวมตัวอย่างที่คู่มือเฉลยเอง + ตรวจตรรกะ 29 ข้อ · เคสขอบทุกจุดตัด · ค่าที่เป็นไปไม่ได้ถูกปฏิเสธพร้อมข้อความ

## ข้อมูลและความปลอดภัย
- ใช้ข้อมูลสมมติเท่านั้น ฐานข้อมูลไม่มีคอลัมน์ชื่อ HN หรือเลขบัตร · ช่องข้อความอิสระมีคำเตือนห้ามพิมพ์ข้อมูลจริง
- ไม่ล็อกอิน = เคสอยู่ใน localStorage ของเครื่อง · ล็อกอินและยินยอมแล้ว = Supabase ภูมิภาค Singapore เปิด RLS ทุกตาราง ยิง API ด้วย anon key โดยไม่ล็อกอินได้ `[]`
- ความยินยอมกั้นที่หน้าแอป: ยังไม่ยินยอมข้อ 1–2 แอปจะไม่ส่งเคสเข้าฐานข้อมูล · ฐานข้อมูลยังไม่ตรวจความยินยอมเอง
- `supabase-config.js` มีแค่ anon key ที่ออกแบบให้อยู่ฝั่งเบราว์เซอร์ ความปลอดภัยอยู่ที่ RLS ซึ่งกันผู้ที่ไม่ล็อกอินแล้ว · สิทธิ์ของผู้ที่ล็อกอินกำลังปรับให้เข้มขึ้น ดู PRODUCTION-PLAN · service_role key ไม่อยู่ในรีโปและไม่เคยอยู่ในประวัติ git
- รีโปเปิดสาธารณะเพราะเป็นงานเรียนที่ผู้ตรวจต้องเปิดดูได้ และ GitHub Pages แบบฟรีบังคับ public
- ผู้รับผิดชอบข้อมูล: ผู้พัฒนา · ขอลบบัญชีหรือแจ้งเหตุผ่าน [Issues](https://github.com/mikeysi124/ccme-vibecode-w5/issues) โดยไม่ใส่ข้อมูลส่วนบุคคล · [นโยบายและแบบขอความยินยอม](docs/privacy-policy-consent-v1.0.pdf)
